# 云同步配置（Supabase）

跨设备同步用 [Supabase](https://supabase.com) 的免费层实现：账号登录由它托管，词库和学习记录存在它的 Postgres 里。

选它的理由：免费层是**永久的**（不是试用），注册即开通、没有审批环节，内置账号体系和行级权限，不需要自己写后端。

## 一、创建项目（约 3 分钟）

1. 打开 <https://supabase.com>，用 GitHub 账号登录。
2. **New project**，填项目名（比如 `shici`），数据库密码随便设一个强密码并**记下来**。
3. Region 选离你近的：能选的话挑 `Southeast Asia (Singapore)` 或 `Northeast Asia (Tokyo)`，国内访问延迟低一些。
4. 等 1-2 分钟，项目初始化完成。

## 二、建表（1 分钟）

进入 **SQL Editor**，把 `supabase/schema.sql` 全文粘进去，点 **Run**。

它会创建 `user_kv` 表并开启行级安全（RLS）—— 这条策略保证每个用户只能读写自己的数据，是账号隔离的根本保障，别删。

## 三、关掉邮箱验证（30 秒）

**Authentication → Sign In / Providers → Email**，把 **Confirm email** 关掉，保存。

应用用的是「用户名 + 密码」，内部会把用户名映射成一个合成邮箱交给 Supabase。开着邮箱验证的话，注册后拿不到会话、无法直接登录。

## 四、填配置（30 秒）

**Project Settings → API**，复制两个值：

| 控制台字段 | 填到 `.env.local` |
|---|---|
| Project URL | `VITE_SUPABASE_URL` |
| `anon` `public` | `VITE_SUPABASE_ANON_KEY` |

```bash
cp .env.example .env.local
```

然后编辑 `.env.local`：

```ini
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....
```

## 五、重新构建

Vite 在**构建时**把这两个值内联进产物，所以改完 `.env.local` 必须重新构建：

```bash
npm run build:app     # 网页 / 开发调试
npm run dist          # 打 Windows 安装包
```

## 验证是否生效

1. 打开应用 → 账号页，应看到「云同步 · 已开启」。
2. 注册一个账号，背几个词。
3. 换一台设备（或另一个浏览器）用同一账号登录，词库和学习进度应该自动出现。
4. 账号页的「立即同步」可以手动触发一次。

`#/debug` 页面里搜 `cloud` 能看到每次推送和拉取的日志。

## 实现说明

同步层在 `src/core/cloud.ts`，没有引入任何 npm 依赖，直接调 Supabase 的 REST 接口：

- `CloudAuthProvider` 实现 `AuthProvider`，替换原来的 `LocalAuthProvider`
- `SyncDriver` 包装本地 `StorageDriver`：读走本地，写先落本地再异步推送
- 云端表 `user_kv` 是纯键值结构，键名和本地 IndexedDB 完全一致（`u:<userId>:cfg:settings` 这种），所以同步层不需要任何字段映射
- 冲突策略：换设备登录时以云端为准；本地有而云端没有的键会补推上去

## 注意事项

**免费项目会因长期不活跃被暂停。** Supabase 免费层在项目 7 天没有任何请求时会自动 pause，之后需要去控制台手动恢复。背单词是每天都会打开的应用，正常使用不会触发；如果打算长期不用，建议加一个 GitHub Actions 定时 ping，或者干脆接受手动恢复。

**anon key 可以放在前端代码里。** 它只标识项目、本身不带权限，真正的隔离靠 RLS 和数据库策略。不要外泄的是 `service_role` key——那个绝对不能出现在前端。

**国内网络。** `*.supabase.co` 在国内时好时坏。因为同步是「本地优先 + 后台补传」，网络抖动不会影响背单词，只影响同步的及时性。如果确实需要稳定，可以用 Cloudflare Worker 给自己的域名做一层反代，然后改 `VITE_SUPABASE_URL` 指向它。

**想换平台。** `cloud.ts` 是唯一的云端耦合点。换成腾讯云开发或自建后端，只需要重写这一个文件里的 `CloudAuthProvider` 和 `SyncDriver`，上层 `store.ts` 和所有页面都不用动。
